# 功能指南

用 Go 和 [Viva](https://github.com/vivaui/viva) 编写的原生 Git 客户端，内置项目浏览与工作树文本编辑、中英双语界面与可选的 AI 提交说明。界面与交互参照最新版 IntelliJ IDEA 的新 UI（Islands 主题），目标是低内存，并保证 Git 状态正确。

设计文档见 [docs/design.md](design.md)，架构决策见 [docs/decisions](decisions/README.md)。

## 功能

- **欢迎页**：最近项目（支持搜索和移除，不存在的路径标红）、打开、克隆、新建仓库，也可以把文件夹拖进窗口。搜索框在有查询词时同时匹配工作区里已添加的仓库，因此最近列表装不下的项目也能直接找到并打开，见 [0041](decisions/0041-commit-time-and-clock-format.md)。默认只按仓库名称做子串匹配；搜索框右侧的 Name / Path 可切到完整路径（子序列匹配），用于按父目录或路径片段筛选，见 [0044](decisions/0044-repository-name-search.md)。
- **多仓库工作区**：欢迎页或项目菜单的 Repositories 可添加仓库、统一查看分支与改动、切换和移除条目。打开不是仓库的父目录时，Viff 会提供发现对话框，扫描并勾选其中的子仓库批量导入（包括仓库内嵌套的仓库、submodule 与 linked worktree）；扫描在后台执行、可取消，结果不会自动改变工作区，见 [0036](decisions/0036-repository-discovery.md)。点击文件会先切到所属仓库再查看 Diff；移除不删除磁盘文件，切换保留当前窗口内各仓库的提交说明草稿。工作区里有多个仓库时，Project 面板会用 Workspace 根节点列出它们，行内显示分支与改动摘要，点击非活动仓库即切换，见 [0046](decisions/0046-multi-repository-projects.md)。
- **远程仓库（SSH，只读）**：欢迎页或项目菜单的“打开远程仓库…”输入主机（`dev`、`me@host:2222`）与服务器上的绝对路径（`/srv/app`）。Viff 用系统 `ssh` 在服务器上执行 Git，读取状态、历史、diff、引用、文件树与工作树文件；不会暂存、提交、fetch/pull/push 或修改服务器。认证继承 `~/.ssh/config`、ssh-agent 与 known_hosts；首次连接前需在终端信任主机密钥，当前不提供密码输入框。文件变化靠每 5 秒轮询 `git status`（每第 6 次轮询补一次完整元数据刷新，以看到服务器上新建的分支/标签），没有本地文件监听；编辑、冲突逐块接受、终端、外部打开、ripgrep、交互式 rebase、worktree/submodule 增删都在该模式下禁用，但 worktree/submodule 列表仍可只读查看。见 [0043](decisions/0043-remote-ssh-readonly.md)。
- **Commit 工具窗口**
  - 分组：Merge Conflicts / Staged / Changes / Unversioned Files，可按目录分组。
  - ChangeList：创建、重命名、删除清单，右键分配文件并按清单筛选。筛选仅影响未暂存和未跟踪文件；始终显示全部已暂存文件，提交仍包含全部暂存内容。筛选后的批量暂存只作用于可见文件。
  - 暂存：悬停行上的 +/−，空格键，多选（Shift、⌘）后批量暂存，回滚，加入 .gitignore。
  - 复选框：每行前的复选框可勾选单个文件、目录或整组，暂存、取消暂存、回滚、查看 diff 等批量操作作用于勾选的文件；点框只切换勾选，不触发行本身的单击行为。右键已勾选的文件、目录或整组时保留现有勾选与跨组多选，不清空选择；折叠节点里已勾选的文件仍计入批量操作，实际作用范围与勾选状态保持一致。
  - 提交：Amend，Sign-off，跳过钩子，⌘↩ 提交，“Commit and Push…”。按钮上方常驻说明“Commit staged files only”：勾选只决定批量操作范围，不会自动暂存；有勾选的未暂存或未跟踪文件时显示“N selected files are not staged”和 Stage Selected，点击只暂存这些勾选文件，已暂存但未勾选的内容保持不变；冲突文件仍按 Resolve 流程处理，不进入 Stage Selected。没有配置远端时“Commit and Push…”不可点，悬停提示添加远端。
  - 折叠说明：说明输入区左侧的箭头可把输入框、拖拽条与两个提交按钮一起收起，把空间让给变更树；折叠状态在会话内保留。
  - AI 生成说明：Amend 行右侧的 AI 按钮按当前生效的规则生成一条提交说明并填入输入框，不自动提交；端点、密钥与模型在设置的 AI 页配置，默认关闭，见 [0027](decisions/0027-ai-commit-message.md)。右键该按钮可切换提交信息规则、按项目分别选择或自行编写规则，并有一个「生成前先确认」开关；该开关默认开启，点击按钮先确认再发请求，关闭后点一下即生成，见 [0035](decisions/0035-ai-prompt-rules.md)。按钮提示会显示当前生效的规则名，便于确认这次用的是哪一条。
  - 正在进行 merge、rebase 等操作时显示横幅，带 Continue / Abort。
- **Project 面板**：左侧 stripe 的文件夹图标或 ⌘1 打开，与 Commit 面板共用停靠区。顶部是仓库根节点（名称 + 路径）、工具条（Refresh、Collapse All、Expand All、Open File、Hide）和过滤框；下面是工作树的索引文件与未跟踪文件（ignored 除外），按目录折叠，按 Git 状态给文件名着色。工作区里有多个仓库时，根节点变为 Workspace，下面列出每个仓库及分支/改动摘要；活动仓库保留原有文件树，非活动仓库只显示仓库行，点击后才切换并加载它的文件树，见 [0046](decisions/0046-multi-repository-projects.md)。单击文件在预览页签中只读打开，双击固定；右键可外部编辑、看 blame、看文件历史、复制路径或在文件管理器中显示。⇧⌘O 打开 Quick Open，输入路径片段后回车打开，见 [0024](decisions/0024-file-browser.md)。工作树里的 UTF-8 文本文件可在查看器工具栏点 Edit（⌘E）进入编辑模式，见[应用内编辑](decisions/0042-in-app-editing.md)。
- **Stash 页签**：储藏（可包含未跟踪文件、保留索引）、应用、Pop、删除、转为分支，并可查看 stash 中的文件 diff。
- **补丁**：变更列表右键“Create Patch…”把选中的改动保存为 `.patch`（二进制和 CRLF 原样保留，重命名仍是 rename）；Git 工具窗口菜单可以把补丁应用到工作树或只应用到索引，应用失败时文件不变并显示 Git 的原始错误。
- **Diff**
  - 并排与统一两种视图，同步滚动，曲线连接相同块，词级高亮，按语言语法着色。并排视图可拖动两条对比栏之间的分隔条调整左右宽度，聚焦分隔条后也可用左右方向键调整，双击恢复默认比例；比例保留在当前页签。
  - 横向滚动：最长的一行超出并排视图较窄的一栏（或统一视图的正文宽度）时，diff 底部会出现一条横向滚动条，并排视图两侧共用同一偏移、拖动时两栏同步；滚动条占用底部独立高度，不覆盖最后一行，右端让开改动标记或竖向滚动条，没有超长行时不显示。滚轮横向滚动与 Shift+滚轮仍可直接使用。
  - 折叠未更改片段：diff 中超过几个上下文行的相同代码默认收成一行「未更改的 N 行」，点击该行或聚焦后按 Enter / Space 即可展开；diff 工具栏的「折叠未更改的片段」按钮可整体关闭或重新开启折叠，并排与统一视图共用同一份折叠状态，见 [0045](decisions/0045-diff-folding-and-pane-resize.md)。
  - 跳转到源：diff 工具栏的编辑图标打开当前视图对应的文件——工作区 diff 打开工作区文件并刷新一次 Git 状态，提交 diff 打开该提交里的版本；同一来源已有页签时复用它并固定，没有时才新建。冲突视图与文件查看页签用的是各自的工具栏，不提供这个动作。
  - 文本选中：并排与统一视图的行内容都可鼠标拖选、双击选词，⌘C 复制、⌘A 全选（复制原始行内容，不含行号与 +/- 前缀）；并排视图两侧各自独立选中，互不串扰。
  - 改动标记：diff 右边缘一条窄带，只标出改动所在的段落（新增、删除、修改各一种颜色），不画代码本身；半透明框标出当前可视范围，按下或拖动可直接滚到该位置。它占的就是滚动条那一列并兼作滚动条，所以两者不会并排抢位置。设置 → General 的「在 diff 旁显示改动标记」可关闭，关闭后恢复普通滚动条。
  - 代码缩略图（可选，默认关闭）：只在只读文件查看器右侧出现，把整份文件压成一条窄列，每行按语法着色，看得出缩进与代码疏密；半透明框标出当前可视范围，拖动它或点击别处即可定位。文件查看器工具栏的「代码缩略图」按钮切换显示，设置 → General 的「在文件查看器右侧显示代码缩略图」是同一个开关。
  - 部分暂存：块按钮（→ ← + ⟲）可暂存、取消暂存或回滚单个块，也可以在行号栏选中几行后只暂存这些行。
  - F7 / ⇧F7 在差异之间跳转，⌘F 搜索，可忽略空白差异，F4 用外部编辑器打开。
  - 预览页签跟随选中的文件；双击或 ⌘D 固定页签。
  - 图片预览：PNG / JPEG / GIF（仅首帧）在 diff 中并排显示，等比缩放并标注格式、像素尺寸与文件大小；超过内容读取上限的图片仍按“文件过大”处理。
- **冲突查看器**：Ours / Result / Theirs 三栏，在冲突块间跳转，可逐块接受 Ours / Theirs / Both；修改后先检查结果，再标记为已解决。支持在外部编辑器中自由编辑；横幅的 Copy for AI（以及每块的 Copy This Block）把仓库、文件、操作、双方来源与冲突块原文复制到剪贴板，交给外部 AI 修改——Viff 不调用模型、不联网，外部保存后自动刷新，仍由你手动标记已解决。
- **文件查看**：只读打开某个提交里的文件（“Open Repository Version”），显示行数、换行符，以及二进制、超大文件和子模块的说明；工作树文件可定位到当前行用外部编辑器打开（F4），历史版本不提供这个动作。工作树里的 UTF-8 文本文件（原始文件和编辑后内容都不超过 1 MiB）可通过工具栏的 Edit 或 ⌘E 进入编辑模式：保留行号、水平滚动与语法着色，⌘S 保存，Revert 还原到最近一次保存或重新加载的内容，Done 返回只读查看；保存时会恢复原行尾与 UTF-8 BOM、保留文件末尾是否有换行，并重新读取磁盘，内容被外部改动或文件消失时拒绝覆盖并提供 Reload。历史版本、diff、冲突、二进制、子模块和符号链接仍然只读，见 [0042](decisions/0042-in-app-editing.md)。
  - **Git blame 注解**：按提交新旧着色，显示作者与日期；点击注解在日志中定位该提交，右键可看该提交的 diff 或注解上一个版本。
- **浏览提交的仓库树**（“Browse Repository at Revision…”）：在日志里右键一个提交，列出该提交里的全部文件（路径、大小，并标出可执行、符号链接和子模块），可按路径过滤，双击或回车以只读方式打开该版本。
- **在文件中查找**（⇧⌘F）：与 ⇧⌘O 的 Open File 共用一个双页签对话框；Contents 页搜索工作树里的文件内容，列出相对路径、行号与该行文本，回车以只读方式打开命中行。每次查询直接读取工作树，不建索引，结果最多 300 条；遵守 Git 跟踪与 `.gitignore`，跳过二进制。默认后端为 `auto`（已安装 ripgrep 时优先，否则 Git grep）；ripgrep 不随应用打包，可在 设置 → General → Search 填路径，或从 <https://github.com/BurntSushi/ripgrep/releases> 下载，见 [0037](decisions/0037-content-search.md)。
- **子模块**：Git 工具窗口的 ⋯ 菜单列出子模块的状态（未初始化 / 已修改 / 冲突）、当前提交和 describe，可 Update、Sync 或打开子模块；变更列表里子模块条目的右键菜单也有 Update Submodule 与 Open Submodule。递归子模块一并列出；可以添加子模块，或确认后移除、停用（deinit）当前仓库的直接子模块，脏内容需要明确确认强制操作。
- **Git 工具窗口**
  - 日志：分支树；提交图；引用标签；按文本或哈希、分支、作者、日期、路径过滤；懒加载。点开「分支」后可直接输入名称搜索本地分支、远端分支和标签，用 ↑/↓ 选择、Enter 应用，或按 Esc 取消。
  - 提交详情：文件列表和可滚动的完整提交信息；多选提交显示受影响文件的去重并集，点击文件可查看来源提交的 diff。
  - 提交右键菜单：cherry-pick、revert、reset（Soft/Mixed/Hard/Keep）、撤销提交、检出、新建分支或标签、与工作树比较；选中两个提交可比较它们之间的文件。
  - 直接编辑历史：修改提交信息、把提交 squash 进父提交、删除提交（drop），冲突时自动 abort 并保持分支不变。
  - 控制台显示所有执行过的 Git 命令及其输出，支持长行横向滚动；引用日志页签可以查看 reflog。
- **分支弹窗**（⌥⇧`）：速搜、收藏、本地和远程分支的子菜单，可执行检出、新建、重命名、合并、rebase、比较、设置上游、推送、删除；“Show Changed Files”列出两个分支 tip 之间的文件，双击打开 diff。
- **双击分支检出的开关**：日志左侧分支树里双击分支默认只选中该分支并筛选日志，不改动工作区；设置 → General → 行为的「双击分支时检出该分支」打开后才检出，走与右键 Checkout 相同的入口（已被其他工作树检出的分支会改打开那个工作树）。关闭状态下右键菜单仍可检出。工作区有未提交改动时照旧按 Smart Checkout 先确认，不自动 stash、不丢弃改动，见 [0040](decisions/0040-branch-double-click.md)。
- **网页入口**：Log 单提交右键“Open Commit on GitHub/GitLab/…”，分支弹窗里本地分支可打开分支页、与基准分支比较、打开创建 PR / 合并请求的页面。只生成服务地址并用系统浏览器打开，不登录、不调用 API；Bitbucket 不生成比较与创建 PR 页面，改为打开分支页并提示。
- **撤销**：⌘Z 撤销本会话内最近一次本地操作（提交、Amend、merge、rebase、cherry-pick、revert、reset、检出、分支新建/删除/重命名）。撤销前重新校验 HEAD、分支与工作区，状态不匹配就拒绝；保留最近 20 条，切仓库清空，不持久化。
- **Git LFS**：自动检测规则和缺失依赖，复用仓库状态发现属性文件。规则刷新失败时保留上次结果，在 LFS 提示中显示原因；手动刷新仓库可重试。点状态栏的 `LFS` 或从 Git 工具窗口菜单选「更新 LFS 统计」，才会统计受管文件；菜单可复制有效的文件清单。状态栏显示数量和统计状态，提示内显示上次统计时间。缺 git-lfs 时，提交面板给出警告和可复制的安装命令。Viff 不管理 LFS 对象。
- **Smart Checkout**：工作区有未提交改动时切换分支或检出修订不再直接失败——Git 因改动会被覆盖而拒绝后弹出确认，选“Stash and Checkout”会连同未跟踪文件一起 stash，检出后自动恢复；恢复冲突时改动留在 stash 并提示，检出失败则恢复改动、当前分支不变。
- **工作树（Worktrees）**：分支弹窗底部的“Worktrees…”列出仓库的所有工作树（分支、短 HEAD、路径，当前工作树有标记），可以新建（创建新分支或选择未被占用的已有本地分支，路径按分支名建议）、删除（可强制丢弃改动，分支保留）、打开为当前仓库、复制路径；已被其他工作树检出的分支在分支菜单里标注，检出会打开那个工作树。
- **推送和更新**：推送对话框列出待推送的提交，可选推送标签和 force-with-lease；更新支持 merge、rebase 或只允许快进，Update Project 对话框里的“不再询问”勾选后，⌘T 直接用记住的方式更新并以通知反馈（设置 Git 页的“询问更新方式”可改回，恢复每次询问）；也支持 Fetch、后台定时 Fetch 和管理远程仓库。
- **推送变体**：日志右键“Push Up to Commit…”把某个历史提交及其之前的提交推到远端分支；分支弹窗“Push to Another Remote…”把 HEAD 推到别的远端或分支名；标签菜单可以只删除远端标签（本地标签保留）。非 fast-forward 默认被 Git 拒绝并显示原文，强制推送需显式勾选 force-with-lease。
- **更新未检出的分支**：分支弹窗里非当前分支的本地分支有“Update from Remote”，快进到远端同名分支并说明前进了几个提交；分叉时拒绝且分支不变。浅克隆时 Git 工具窗口的 ⋯ 菜单会多出“Fetch Full History (Unshallow)”。
- **设置对话框**：分组标题（外观、行为、Git 可执行文件、Subversion 可执行文件、工具、诊断、更新、字体、搜索）可点击折叠；内容比窗口高时正文自动改为可滚动的区域并显示滚动条，OK / Cancel 固定在窗口内始终可点，滚轮与 PageUp / PageDown 都能滚动，Tab 到视野外的字段时正文会跟随滚动。分组标题前的展开/收起指示使用与项目树一致的矢量箭头。行为分组的「时间格式」在 24 小时制（默认）与 12 小时制（带 AM/PM）之间切换，作用于提交列表、提交详情、blame 提示、通知与命令控制台；时间一律按本机时区显示，见 [0041](decisions/0041-commit-time-and-clock-format.md)。
- **Git 设置**：设置对话框的 Git 页可以指定 SSH 命令、GPG 程序、签名格式（Git 默认 / OpenPGP / SSH）、签名密钥、默认签名提交与 credential helper，也可以关掉“询问更新方式”让更新不再逐次询问；保存后对下一次 Git 调用立即生效，不改写仓库或全局 Git 配置。
- **终端工具窗**：左侧 stripe 的终端图标或 ⌥F12 在底部打开，当前目录是打开的仓库。支持 5000 行回看、滚轮与滚动条、拖选复制、粘贴（含 bracketed paste）、清屏、重启与拖动高度；隐藏工具窗或切换仓库不结束 shell；重启、关闭项目（有运行中的 shell 时先确认）或关闭窗口才结束进程。实现与边界见 [0028](decisions/0028-integrated-terminal.md)。
- **通知**：右下角气泡（成功消息 10 秒后自动隐藏），以及通知工具窗口。对话框打开期间不画气泡：气泡绘制在窗口内容之上，会盖住并吞掉对话框按钮的点击；通知不会丢，关掉对话框后按完整时长重新显示。
- **应用内更新**：`Help → Check for Updates…` 或启动时自动检查；发现新版本后应用内下载、用 `SHA256SUMS` 校验，点“Restart to Update”自动替换并重启，不需要打开浏览器。Windows 使用便携 ZIP，Linux 便携包使用 tar.gz；DEB 安装需要 `sudo apt install` 完成。
- **界面语言**：默认英文，设置 → General → Language 可切到简体中文；菜单、对话框、工具窗口与通知随语言切换，Git 命令与输出、路径与哈希、快捷键与日志字段保持英文。
- **主题**：Islands Dark、Islands Light，或跟随系统。
- **窗口位置**：记住上次关闭时的位置和尺寸，包括放在副屏上的位置，下次启动就在原处打开；位置对应的显示器不存在时回落到主屏，见 [0034](decisions/0034-window-geometry.md)。

## 构建与运行

需要 Go 1.27 或更高版本，以及本机安装的 `git`。在 macOS 上编译需要 Xcode Command Line Tools，因为字体注册和 FSEvents 用到了 cgo。

```sh
go run ./cmd/viff                 # 打开上次的项目，没有则显示欢迎页
go run ./cmd/viff ~/code/project  # 打开指定仓库
go build -o viff ./cmd/viff
```

设置保存在用户配置目录的 `Viff/settings.json`（macOS 上为 `~/Library/Application Support/Viff/settings.json`） 中，也可以通过设置对话框（⌘,）查看路径。

## 已知限制

- 多仓库写入操作只针对当前仓库；非活动仓库在打开总览或手动刷新时更新。Project 面板的 Workspace 分组只做导航与切换，非活动仓库不加载文件树，也不提供跨仓库提交/推送，见 [0046](decisions/0046-multi-repository-projects.md)。ChangeList 是文件分组，不提供独立索引或跨仓库提交，见 [0020](decisions/0020-repositories-changelists.md)。从父目录发现仓库按名称跳过依赖/构建目录，默认深度 4、目录 2000、仓库 200；超出或跳过时对话框会提示，见 [0036](decisions/0036-repository-discovery.md)。
- 已在 macOS，以及 Windows Server 2022 x64（Git 2.56.0.windows.4）上验证 Git 功能和 Viva 无头界面。Windows 本地 NTFS/ReFS Git 仓库使用原生文件监听，空闲时每五分钟校验一次；Linux、WSL、网络路径和其他不支持原生监听的 Windows 仓库仍使用轮询。见 [0049](decisions/0049-windows-native-file-watching.md)。
- 界面字体默认为系统字体（SF Pro），没有使用 Inter；设置里可分别选择「界面字体」（全部已安装族）与「diff 字体」（仅等宽族，用于 diff、控制台与哈希），见 [0002](decisions/0002-fonts.md)。
- 冲突支持逐块接受两侧内容；自由文本编辑、二进制或不可靠冲突标记仍需要外部编辑器，见 [0019](decisions/0019-git-issue-gaps.md)。Copy for AI 只写系统剪贴板，不调用模型、不发网络请求；单块 200 行 / 20 KB、全文 200 KB 截断，见 [0032](decisions/0032-ai-conflict-context.md)。
- 撤销只在当前会话、当前仓库生效，保留最近 20 条；首次提交、reword/squash/drop、冲突后 continue、reset --soft/--mixed 的撤销不支持，也没有 redo，见 [0030](decisions/0030-undo.md)。
- 网页链接不做 OAuth/API：未知主机的页面布局按 GitHub 猜测，Bitbucket 不生成比较与创建 PR 页面，未推送的分支由服务端提示不存在，见 [0029](decisions/0029-pr-links.md)。
- LFS 只检测不管理：不安装 git-lfs、不执行 git lfs install/track/pull/push；未暂存的 LFS 指针文件不计入列表，见 [0031](decisions/0031-lfs.md)。
- 已有分支创建工作树见 [0018](decisions/0018-existing-branch-worktree.md)；prunable 工作树只能查看、不能删除。嵌套子模块的移除和 deinit 需要先打开其所属仓库，见 [0019](decisions/0019-git-issue-gaps.md)。
- Project 面板与 Commit 共用左侧停靠区，不能同时显示；默认显示 Commit，按 ⌘1 打开 Project。ignored 文件默认不显示，折叠状态不持久化；Project 中打开的图片仍只显示二进制说明（diff 的图片预览不适用于单版本查看）；文本支持鼠标拖选、Shift+方向键与 ⌘A/⌘C 复制（制表符按显示展开为空格），但不支持拖选自动滚动。工作树文本文件可显式进入编辑模式，但只支持 UTF-8，原始文件和保存后的内容都不超过 1 MiB；行尾只按第一处换行判断，混合行尾或只有 `\r` 的文件会归一化为检测到的类型，BOM 与末尾换行保留；没有补全、跳转、多光标或自动保存，编辑模式内外部修改只能用保存失败通知里的 Reload 放弃本地缓冲，或点 Done 退出后重新读取；通知里的 Reload 只覆盖内容被改动或文件消失。冲突文件仍只读。关闭窗口、从菜单退出、移除当前仓库和切换仓库前都会确认未保存的修改；安装更新后的自动重启不经过确认，更新前需自行保存。见 [0024](decisions/0024-file-browser.md) 与 [0042](decisions/0042-in-app-editing.md)。
- 界面语言覆盖主要窗口；少量相对时间提示（如“Moments ago”“Today 14:30”）与诊断 issue 模板仍是英文。
- 提交信息的编码只做容忍不做还原：读取时非法 UTF-8 字节替换为 U+FFFD，其余提交照常显示（过去一条坏 revision 会让整个日志视图报错）；仓库里已经双重编码成乱码的提交信息不会自动修复，需要外部工具改写历史，见 [0041](decisions/0041-commit-time-and-clock-format.md)。
- AI 生成提交说明默认关闭；启用后会把当前改动的分支名、最近五条提交、变更文件与 diff 发到你自己配置的端点，范围与隐私边界见 [privacy.md](privacy.md)。自定义的规则文本同样会随请求发送；规则只影响模型的指令，不会改变发送范围与截断上限。模型返回的文本原样填入提交框，Viff 不解析结构。规则选择：仓库自己的选择优先，没选过的仓库沿用你上一次在任意项目选中的规则，两者都没有时用内置规则；选中内置规则会同时清空「上一次使用」。
- 应用内更新没有系统签名校验（macOS ad-hoc 签名、Windows 无 Authenticode），只做 HTTPS + SHA-256；宿主的系统安全提示仍可能出现。DEB 安装受权限限制只能提示手动安装；随包文档在 Windows/Linux 自替换后保持旧版本，见 [0023](decisions/0023-app-update.md)。旧版本（v0.1.0 及更早）没有更新器，升级到第一个带更新器的版本需要手动下载一次。
- Subversion 支持见 [0025](decisions/0025-svn-support.md)，其限制与 Git 不同：
  - 历史查询需要访问仓库（网络或 `file://`），因此保留本地缓存；离线时显示缓存并显式标注为陈旧，此时看到的历史不是最新。
  - 没有暂存区，提交改用显式的提交目标集；`Ahead` 恒为 0，「有远程更新」由工作副本 BASE 与仓库 HEAD 比较得出。
  - 提交是远程原子操作，没有本地提交；提交完成后无法在本地撤销，中断后须重新查询工作副本确认是否已提交，不自动重试。目录过期时 SVN 自身会拒绝提交，需要先 update。
  - 不支持 rebase、stash、worktree、reflog、submodule；这些入口按能力位隐藏，而不是显示后报错。
  - 分支是目录约定加 `switch` 语义，不是轻量引用，所以「分支」操作的效果与 Git 不同。
  - 冲突解决后会在工作副本留下 `.mine` / `.r2` / `.r3` 辅助文件；Viff 已把它们从状态列表中过滤，但用户仍可能在文件系统里看到。
- 远程仓库是只读观察模式：只能使用 key/agent 认证，不弹密码/口令；服务器需为 Linux/macOS 并安装 Git，不支持 Windows 的 OpenSSH 服务器；本机设置里的 Git 路径、签名、凭据助手与 SSH 命令对远程仓库不生效。fetch/pull/push、应用内编辑、冲突接受、终端、外部打开、ripgrep、交互式 rebase 与 worktree/submodule 增删均不可用（worktree/submodule 面板可只读查看）；刷新依赖 5 秒轮询并每 30 秒补一次元数据刷新，未做连接复用。见 [0043](decisions/0043-remote-ssh-readonly.md)。
- 终端目前只有一个本地会话：不连 SSH、不支持多标签/分屏、搜索、链接、内联图片与鼠标上报；隐藏工具窗时 shell 继续运行，会话不跨重启恢复。切换仓库不会改写已在运行的 shell 的当前目录，新会话才从新仓库根目录开始。Windows 使用 ConPTY（需要 Windows 10 1809+），本机未做 Windows 实机验收。见 [0028](decisions/0028-integrated-terminal.md)。
- Windows 版可直接打开 WSL 发行版内的仓库（`\\wsl.localhost\...` 或旧的 `\\wsl$`，两种写法视为同一仓库）：Git 由发行版执行，文件经 9P 读取，因此 diff 与刷新比本地磁盘慢；设置里针对 Windows git 的取值（Git 路径、GPG 程序、签名密钥、凭据助手、SSH 命令）对 WSL 仓库不生效，认证、签名与 hooks 全部取自 Linux 侧。文件监听在 WSL 仓库上放宽到 5 秒。内置终端与 `rg` 内容搜索仍走 Windows 侧，未针对 WSL 适配。见 [0038](decisions/0038-wsl-repositories.md)。
